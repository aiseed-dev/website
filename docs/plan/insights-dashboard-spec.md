# aiseed.dev 構造指標ダッシュボード (Insights) 仕様書 v0.1

## 0. 目的

Insights — 構造分析 (全26章) の論旨を支えている**構造的な数値**を一覧表示する。
読者が記事の主張を「数字の側」から検証できる場を作る。

[物理量ダッシュボード](physical-dashboard-spec.md) の姉妹編:

| | 物理量ダッシュボード (/dashboard/) | 構造指標ダッシュボード (/dashboard/structural/) |
|--|--|--|
| 対象 | 価格・流量・在庫・残り日数 (日次〜月次で動く) | 構造定数・依存率・長期トレンド (年次でしか動かない) |
| 出所 | API・市場データ | 統計機関・研究論文 (Insights 記事が引用したもの) |
| 更新 | cron 自動取得 | 年次の手動更新 (出典の改定時) |

**ダッシュボードは主張しない** (物理量ダッシュボードと同じ編集方針)。
値・単位・観測時点・出所、そして**その数字を使った記事へのリンク**だけを置く。
結論は記事の側にあり、ここには載せない。

## 1. 設計原則 (物理量ダッシュボードを踏襲)

- 素の HTML/CSS/JS、ビルド工程なし。**フロント部品は /dashboard/js/ を再利用**し、
  1行も複製しない (renderIndicatorCard / renderChokepointSection / kindBadge /
  sparkline はデータだけで完結する設計だったので、そのまま使える)
- 単一データモデル: 新指標 = 1レコード追加。テーマ (theme) は物理量側の
  chokepoint と同形なので、セクション描画も共通
- 記事との相互リンク: 各指標に `article: {href, label}` を持たせ、カードから
  記事へ飛べる (逆方向は記事から `#indicator-<id>` アンカー)

## 2. データ

`html/dashboard/structural/data/structural.json` (追跡ファイル。v1 は手動キュレーション):

```json
{ "generated_at": "...", "spec": "docs/plan/insights-dashboard-spec.md v0.1",
  "themes": [ { "id": "...", "name_ja": "...", "name_en": "...",
                "indicators": [ Indicator... ] } ] }
```

Indicator は物理量ダッシュボードと同一構造 + `article` (任意)。
kind は `constant` (依存率・偏在) を中心に、`flow` (年次で動く系列)・
`price`・`clock` を使い分ける。

値はすべて **Insights 記事が本文で引用している数値** から採る (記事にない数値を
ダッシュボード側で創作しない)。出所は記事が引いた一次出所 (USGS・W3Techs・
WPScan・WHO 等) を記す。

## 3. テーマと指標 (v1: 6テーマ・26指標)

1. **リンと肥料** — リン鉱石偏在 (モロッコ70%)・カリ偏在 (露白40%)・日本の
   リン酸中国依存 (76%)・合成肥料が支える食料 (~50%)・硫黄の副産物率 (~90%)
2. **化石資源と素材** — 石油/ガス可採年数 (~50年)・精製売上のエネルギー比率
   (86%)・プラスチック生産 (4億t/年)・バイオプラ比率 (<1%)
3. **土壌と農業** — 米国表土喪失 (~50%/150年)・土壌炭素の累積/年間喪失・
   被覆作物導入率 (<4%)・みどり戦略2050 有機25%目標
4. **ソフトウェア構造** — WordPress シェア (43%)・年間新規脆弱性 (11,334件)・
   サードパーティ比率 (97%)・パッチ中央値 (70日)・SWE-bench・NVIDIA DC比率
5. **戦争の経済構造** — 迎撃コスト比 (~100倍)・攻撃のドローン比率 (10→70%)・
   ウクライナ防衛産業 ($1B→$35B)・AI航法モジュール単価 (~$50)
6. **医療と社会** — キューバ医師密度 (9人/千人)・同乳児死亡率 (4.0→9.9)・
   東京圏通勤者 (3,600万人)

## 4. 成長

- 記事を書く/更新するたびに、その記事の核になる数値を1レコード追加する
- 年次統計の改定 (USGS MCS 等) で series に追記 → スパークラインが育つ
- 自動化できる出所が現れたら tools/dashboard の fetcher パイプラインに昇格
- /insights/ ハブ (ビルド生成) からのリンクは記事ビルダー側の変更が必要なため
  フォローアップとする。当面は /dashboard/ と相互リンク
