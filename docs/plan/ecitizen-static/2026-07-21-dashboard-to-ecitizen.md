# 物理量ダッシュボードを ecitizen へ移す — 設計書(現実を考慮した改訂版)

作成日: 2026-07-21 ／ 対象: aiseed.dev の [物理量ダッシュボード](../physical-dashboard-spec.md)(v0.1)を
統計メモ帳(ecitizen.jp)へ移設する方針。

> **決定**: aiseed.dev のメニュー「記事 > 物理量ダッシュボード」からリンクを外した
> (2026-07-21)。ダッシュボードの**コードとデータ**(`tools/dashboard/`, `html/dashboard/`)は
> 移設完了まで凍結保存する。本書は「何を・なぜ・どう」移すかの正典。

## 0. なぜ移すか

物理量ダッシュボードは、構造分析(Insights)の論旨を支える**物理量**を一覧する装置として
aiseed.dev に置いた。しかし運用してみて、置き場所として無理があることが分かった。

- **aiseed.dev はエッセイ(分析)のサイト**である。日次で動くコモディティ相場を
  自動取得し続けるライブ・ダッシュボードは、essay サイトには重い。cron・fetcher・
  manual 指標の更新という**運用負債**が、記事を書く手を奪う。
- 指標カタログの実体(ホルムズ原油、ロシア石油の流れ、リン酸肥料、米国食料)は
  **地政学コモディティ**であり、これは記事の中に出典つきで引用する形が本来正しい。
  「主張しないダッシュボード」として常設するより、各記事が必要な数字を本文で示す方が、
  読者の判断材料として文脈がある。
- 一方 ecitizen.jp は、まさに**データのサイト**である。しかも直近で
  「[静的サイト + ビルド時生成](2026-07-07-legacy-to-static.md)」へ移行し、
  一次データを git に凍結する構造になった。ダッシュボードの設計原則
  ——**小さく・自立し・育つ / 静的・ビルド工程なし / Python 標準ライブラリのみ**——は、
  ecitizen の新アーキテクチャと同じ思想であり、**置き場所としてぴったり合う**。

つまり「移設」とは、コモディティ指標をそのまま運ぶことではない。**ダッシュボードの
方法論を、それが本来属するデータ**——ecitizen の人口統計——**に適用し直すこと**である。

## 1. 現実を考慮した改訂 — 何を残し、何を変えるか

### 残すもの(方法論=移設の本体)

| 要素 | 内容 |
|--|--|
| データモデル | `Indicator` / `Point` の単一構造。**新指標 = 1レコード追加** |
| 編集方針 | **主張しない。** 値・単位・観測時点・出所だけを置き、予測も結論も載せない |
| フロント | 静的・ビルド工程なし。重いフレームワーク/バンドラ/コンテナ/常駐なし |
| バックエンド | Python 標準ライブラリのみ、外部依存ゼロ |
| kind 分類 | `price / flow / clock / stock / constant`(そのまま使える) |

### 変えるもの(現実 = ドメインの違い)

- **地政学コモディティ指標は移さない。** ホルムズ/ロシア/リン酸/米国食料は、
  aiseed.dev の Insights 記事の中に出典つき数値として残す(ダッシュボードから記事へ差し戻し)。
- **対象を ecitizen の実データ=人口統計の物理量にする。** ecitizen が扱う量は、
  そもそも物理量ダッシュボードの思想と同型である:
  - **人口・出生数・死亡数**(積み上がる/ゼロに向かう物理量)
  - **高齢化率・従属人口指数**(`constant` に近い構造比)
  - **市町村の存続年数・自然減の加速**(まさに `clock` = ゼロに向かうカウントダウン)
  日本の人口減少は、この装置が最も得意とする「時計」型指標の宝庫である。
- **取得方法(acquisition)の重心が変わる。** aiseed 版は日次 API の `auto` が主で
  運用が重かった。ecitizen のデータは **git に凍結された確定国勢調査(1980〜2015)**が
  中心なので、多くの指標は `constant` / `clock`(凍結データからの計算)になり、
  **cron 取得はほぼ不要**。ライブなのは最新の人口推計くらいで、そこだけ `auto`。
  → aiseed 版で最大の負債だった「manual 指標の更新」と「日次 fetcher」が、
    ドメインを移すだけで**構造的に消える**。これが「現実を考慮した」核心。

## 2. 移設後の構成(ecitizen 側)

```
ecitizen リポジトリ/
├── data/legacy/                 # 既存: git 凍結の確定国勢調査(1741市町村×35年)
├── tools/dashboard/             # aiseed から移植(models/storage/derived/build)
│   ├── models.py                #   Indicator/Point … そのまま
│   ├── build.py                 #   取得 → 計算 → 静的 JSON。取得元を legacy データに向ける
│   └── catalog/
│       ├── indicators.json      #   人口統計の指標カタログ(新規)
│       └── regions.json         #   隘路(chokepoint)→ 地域/市町村の束ね に置換
└── html/dashboard/              # 静的フロント(aiseed の html/dashboard/ を移植)
```

- `chokepoint`(隘路)という束ね軸は、ecitizen では **region(地域・市町村)** に読み替える。
  モデルの構造は変えず、カタログの意味だけ差し替える(方法論の再利用)。
- 出力は `html/dashboard/data/dashboard.json`(フロントが1回 fetch)のまま。

## 3. 今日の主題との接続(なぜこれが正しい形か)

本サイトで今日整理した「[AIは平均を思い出す機械](../../../articles/blog/031-ai-not-ignorance-but-average/ja.md)」
の規律——**出どころを信頼の根拠にせず、一次資料に係留する**——は、実は
物理量ダッシュボードの編集方針「**主張しない。物理量・単位・観測日・出所だけを置く**」と
同じものである。ecitizen の git 凍結国勢調査は、まさに**改変不能な一次資料(正典)**であり、
ダッシュボードはその正典を、加工も主張もせずに提示する。
「[正典検索](../../../apps/canon-search/README.md)」がテキストの正典に対してやることを、
このダッシュボードは統計数値の正典に対してやる。置き場所を ecitizen に移すことは、
方法論を、それが最も正しく働くデータの上に戻すことにほかならない。
