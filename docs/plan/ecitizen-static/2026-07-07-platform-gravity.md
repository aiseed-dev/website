# プラットフォームの重力が消えていく (産業編)

*(ブログ記事ドラフト — 技術編
「[15年運営した動的サイトを「git に凍結」し、同じデータでスマホアプリまで作った話](2026-07-07-legacy-to-static.md)」
の続き)*

技術編では、15年もののASP.NETサイトを静的サイトに移行し、同じデータ
スナップショットから Flutter / Flet のアプリを作った話を書きました。
一人と AI でそれができてしまった、という事実から見えてくる
プラットフォーム勢力図の変化を、こちらにまとめておきます。

## OS の差別化が消えていく

Flutter は全ピクセルを自前で描画するので、OS に求めるのはウィンドウと
入力と GPU だけ。Windows が数十年かけて積み上げたネイティブ描画の資産は、
アプリからもう呼ばれません。フォントすらユーザーの環境に返した今、
今回のアプリは Windows でも Linux でも Chromebook でも同じものです。

アプリ開発の道具立てを並べると、差は残酷なほどはっきりします。
ここで大事なのは、**固有と汎用は別の武器**だということです。
Flutter/Dart のような汎用ツールはどこでも動くからこそ、
プラットフォームの差別化にはならない。勝負を決めるのは、
自分の OS とハードウェアに深く結びついた固有のスタックです。

Apple には Swift と SwiftUI がある — ハードウェアと OS に密着した
固有の武器。Google には固有の Kotlin に加えて、汎用の Dart / Flutter
まである — 今回のアプリを作った道具そのもので、他社の土地でも
開発者を自分の道具に乗せられる。Microsoft の固有は Win32。半世紀近く
前の C の API で、後継は WPF → UWP → WinUI → MAUI と迷走を続けて
どれも本命になれなかった。固有は古び、汎用も持っていない。
これでは勝負になりません。

そしてロックインそのものを AI が溶かしていきます。ロックインの実体は
「固有の知識を習得するコスト」でした — Win32 を覚えた開発者は Windows に
留まる。AI はその習得コストをゼロにする。どの OS のコードも同じ手間で
書けるなら、乗り換えコストは崩壊する。

## Microsoft — AI ファーストの結末

AI に関してはもっとひどい。Microsoft は全製品に Copilot を組み込み、
データセンターに巨額の投資をしていますが、そこで動かす自前の AI が
ない — 中身は他社 (OpenAI) のモデルです。器と配線だけ持っていて、
中身を持っていない。

しかもその OpenAI には逃げられました。専属の計算基盤という関係は
解消され、OpenAI の計算資源は他社連合にも流れています。かつては
OpenAI の巨額の赤字 (計算費) がそのまま Azure の売上 — Microsoft の
黒字 — になる環流構造でしたが、それも細っていく。大型の Azure 購入
契約は残っていますが、この種の契約は総額の枠で、細かい条件まで
固めていないはずです。つまり買う側は値引きを、売る側は値上げを、
いつでも仕掛けられる — 常時交渉の関係です。そして交渉で勝つのは、
代替を持っている側。他に供給先を確保した OpenAI と、中身を他に
持たない Microsoft では、分は明らかです。

つまり力関係が逆転したのです。出発点では、資金も計算資源も
Microsoft に頼る OpenAI という構図でした。今は逆で、OpenAI は
Azure の代わりを持っているが、Microsoft は Copilot の中身の
代わりを持っていない。全製品に他社の頭脳を組み込むというのは、
自社の製品ラインの生殺与奪を相手に渡すということです。
出資で従えたはずの相手に、事業の中身を握られた。

こうして並べると、Microsoft の将来に利益の種が見当たりません。
今の利益は Office と Windows という過去の堀からの収穫で、
その堀は AI が溶かしていく。将来を賭けた AI は自分のものでなく、
そこに注いだデータセンター投資の値打ちは、力関係を逆転させた
借り主との交渉次第。「AI ファースト」を掲げて全部を AI に
賭けた結果、手元に自分の AI がなかった — ナデラの AI ファーストの
結末がこれだとしたら、皮肉な話です。巨大企業の堀ですら、
この速度で無効になる時代だということです。

## 中身を持つ者が強くなった

対照的に、Anthropic は強くなりました。自前のフロンティアモデルを
持ち、特に「コードを書く」という開発の現場を押さえた — 技術編の
一連の作業も Claude との協働です。器 (OS) や配線 (クラウド) ではなく
**中身と使い所**を持っていることが、新しい重力の中心になっている。
Microsoft と OpenAI の関係が示した教訓 — 中身を借りる者は弱く、
中身を持つ者が強い — の、持つ側の実例です。

一方で AI 自体も、オープンウェイトの登場で少しずつ交換可能な部品に
なりつつあります。フロンティアの中身を持つ者と、部品化していく
オープンウェイト。この均衡がどこに落ち着くかは、まだ誰にも
分かりません。ただ確かなのは、「独占的な中身」も「固有の知識」も、
以前より短い寿命しか持たなくなったことです。

## PR という儀式の終わり

同じ力学は、オープンソースへの貢献の常識も変えます。使っている
ライブラリに足りない機能があるとき、これまでの作法は「Issue を立てて
何年も待つ」か「苦労して PR を通す」でした。PR とは何だったかといえば、
**フォークを自分で維持するコストを、上流に外部化するための仕組み**です。
本家に取り込んでもらえば、追従もテストも向こうがやってくれる。
だからレビューの往復にも CLA にも作法にも付き合った。

AI はそのフォーク維持コストを崩壊させました。実例を挙げると、Flutter の
SVG ライブラリが日本語の縦書きに対応していなかったので、本体の
コンパイラに縦書き対応を実装しました — 既存の全テストを通したまま、
半日で。マージされるかどうかは、もう私の問題ではありません。
必要なものは自分の手元にあり、本家が更新されたら AI がパッチを
当て直せばいい。上流には「何が欲しいか」という要件だけを置いてきます。
実装は向こうも AI で数分で再生成できるのだから、コードを送りつける
必要すらない。

貢献が消えるわけではありません。派生パッケージを OSS として公開する
こと自体が貢献であり、誰かがそれを使い、いつか本家がそれを参考にする。
変わったのは順序です — 「本家に入れてもらってから使う」から
「作って使って公開して、本家は好きにすればいい」へ。
個人開発者が巨大プロジェクトの優先順位に人生を左右されない、
ということでもあります。

## 残る堀と、個人開発者の取り分

ただし Apple と Google は、AI では溶けない独自のものを持っています。
Apple はハードウェアと App Store という配布の関門。Google は Android と
Play、Chrome、そして検索という Web の入口そのもの。コードを書く手間が
どれだけ下がっても、利用者に届く経路は彼らの土地を通ります。

だからこそ Web (静的サイト) とアプリの両方を持つ意味がある — Web は
関門のない配布路として残し、アプリはストアの土地代を払う価値がある時だけ。
コードの重力が消えた後に残る差別化は、**配布経路と、自分のデータと、
信頼**です。個人開発者は最初の一つを Web で確保できるし、
二つ目 (自分のデータ) は技術編でやったように git に凍結して
自分の手元に置ける。巨大企業の堀が溶けていく時代は、
個人開発者にとって追い風以外の何物でもありません。
