# aiseed.dev 記事エディタ

WordPress の管理画面に似せた、記事編集専用のデスクトップアプリ(Flet 0.86)。
シリーズ単位 AsciiDoc(`articles/<series>.adoc`)のうち**本文だけ**を編集する。
フロントマターや記事の区切りには触れないので、構造を壊す心配がない
(保存時に必ず再パース検証し、壊れる編集は拒否して元に戻す)。

## 起動

```bash
cd ~/dev/website
./.venv/bin/python apps/site-editor/main.py
```

## 機能(WordPress の管理画面に対応)

| WordPress | このアプリ |
|---|---|
| 投稿一覧 | シリーズ別の記事一覧(検索・状態表示・並び替え↑↓・削除) |
| 新規追加 | 「新規追加」→ スラッグ+タイトルで**下書き**を作成(番号・日付・ラベルは自動) |
| 下書き/公開 | 「公開する」スイッチ。下書きはサイト・索引・sitemapに一切出ない |
| タイトル・抜粋 | タイトル/サブタイトル/説明フォーム(日英タブ) |
| 本文エディタ | AsciiDoc本文(見出し `==`、強調 `*太字*`、リスト、表、Mermaid…) |
| アイキャッチ | hero_image をドロップダウンで指定 |
| メディア | 画像・PDFの追加(ファイル選択)、`image::` タグをコピーして本文へ |
| 更新 | 保存 → 数秒で差分ビルド → プレビューが自動リロード |
| プレビュー | その記事の実ページをブラウザで開く |
| ゴミ箱 | なし。代わりに削除は確認ダイアログ+「変更を記録」(git)で復元可能 |
| リビジョン | 「変更を記録」= gitコミット(メモ付き・最近の記録も表示) |
| サイト公開 | Cloudflare Pages へ「プレビューURL」「本番」の2段階デプロイ |
| （WordPress に無い） | **取り込み** ── Claude Docs などが書き出した Markdown を、下書きの記事にする |

- 並び替え(↑↓)はそのまま prev/next の連載順になる
- どの保存もフロントマター/区切りを再パース検証し、壊れる編集は拒否して復元
- 起動時にプレビューサーバー(ライブリロード付き `tools/serve.py`)を自動起動
  (既に動いていればそれを使う。ポートは環境変数 `AISEED_PREVIEW_PORT`、既定 8000)
- 画像のファイル選択は Linux デスクトップでは `zenity` を使用(`sudo apt install zenity`)

## 取り込み ── Claude Docs で書いた原稿をサイトに載せる

Claude Docs(有料プランで使える)は、文書を claude.ai の中に置く。外から
取りに行けないので、持ち出せるのは書き出した写しだけになる。この口は、その
写しを受け取って、シリーズ `.adoc` の一記事に変えるためにある。

左サイドバーの「取り込む」から、四つの手順で進む。

1. **Markdown を入れる** ── Claude Docs の「書き出し」で Markdown を選び、
   その中身をファイルで渡すか、欄に貼り付ける
2. **変換して確かめる** ── AsciiDoc になったものをその場で表示する。機械変換で
   意味が保てなかった所は「要確認」として並べる
3. **記事の名前を決める** ── スラッグとタイトル。先頭の `# 見出し` があれば
   タイトルに自動で入る
4. **下書きとして取り込む** ── 下書きで作られ、編集画面が開く

変換は移行ツール `tools/convert_md_to_adoc.py` の関数をそのまま借りている。
二つの実装が食い違わないようにするためで、見出し `#`→`=`、強調 `**`→`*`、
リンク、箇条書き、引用 `>`→`____`、表 `|===`、コードフェンス素通しは、記事の
移行時とまったく同じ規約で変換される。

取り込んだあとは、いつもの流れに乗る。編集画面で直し、「更新」でビルドし、
プレビューで見て、「公開する」に切り替え、「サイトを公開」で本番に出す。
*公開してしまえば、読む人に Claude のアカウントは要らない。*

原稿を git に残したいなら、取り込んだあとに「変更を記録」を押す。シリーズ
`.adoc` は文字のファイルなので、直した行だけが差分に出る。
