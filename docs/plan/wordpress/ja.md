# WordPress のフォームで reCAPTCHA を使っていませんか ―― 今すぐ Cloudflare Turnstile に替えるべき理由

## 結論

WordPress の申込フォームに reCAPTCHA を使っているなら、Cloudflare Turnstile のプラグインに置き換えるべきである。無料で、回数制限がなく、クレジットカードの登録も要らない。

理由は三つある。

1. reCAPTCHA の無料枠は月1万回に縮小された。ごく普通のアクセス数のサイトでも月の途中で上限に達し、フォームが止まるか、スパム対策が黙って停止する。しかも、それは運営者から見えない。
2. 課金すれば止まらなくなるが、請求額の上限を決めるのは攻撃者になる。
3. そもそも reCAPTCHA は、通したい相手を止め、止めたい相手を通している。

以下、順に説明する。

## 理由1:無料枠は月1万回 ―― 普通のサイトが月の途中で止まる

Google は reCAPTCHA の無料枠を月100万回から月1万回に縮小した。クレジットカードを登録していないアカウントでは、無料枠を超えた時点で reCAPTCHA はエラーを返す。

この「1万回」は申込件数ではない。reCAPTCHA が動作した回数である。WordPress の定番フォームプラグイン Contact Form 7 の標準的な設定では、reCAPTCHA はフォームのあるページだけでなく、サイトの全ページで読み込まれる。つまり、月1万ページビュー程度のサイトなら、誰一人申し込まなくても、閲覧されるだけで上限に達する。公的機関や支援団体のサイトとして、珍しいアクセス数ではない。

上限を超えた月に何が起きるかは、鍵の種類によって二つに分かれる。

- **フォームが送信を受け付けなくなる。** reCAPTCHA がエラーを返すため、全員の送信が失敗する。申込者には送信失敗の画面が出るが、理由は表示されない。
- **スパム対策が黙って停止する。** Google の公式 FAQ によれば、旧式の v3 鍵は上限超過後、その月の残り期間、全員に固定スコア 0.9(人間とみなす値)を返す場合がある。FAQ には、v3 では超過時に利用者へ表示される通知はない、とも明記されている。

どちらの場合も、超過を知らせるメールが届くのは、鍵を発行した Google アカウントである。数年前に制作業者が設置したサイトなら、通知は業者に届き、運営者には届かない。運営者に見えるのは「フォームが月の後半だけ不調になる」「スパムが月の後半だけ増える」という現象だけで、月が変われば上限はリセットされ、症状は自然に消える。結果として「たまに調子が悪い」で片付けられ、原因の特定はさらに遅れる。

## 理由2:課金すれば止まらないが、請求額は攻撃者が決める

Google が用意した対処は、クレジットカードを登録して課金を有効にすることである。Standard ティアで月8ドル、月10万回まで。ただし、これは平時の金額にすぎない。

第一に、料金は攻撃者が決める。reCAPTCHA はボットのアクセスも1回ずつ数える。月10万回を超えると Enterprise の従量課金に入り、アクセス回数に比例して請求される。防御のための費用が、攻撃を受けた回数で決まる。攻撃者は無料で、防御側だけが支払う。

第二に、支出に上限を設定できない。Google Cloud の予算機能は通知であって、自動停止ではない。カードを登録した時点で支出の天井は消え、止めるには人間が異変に気づいて手動で課金を切るしかない。そして、その異変を知らせる通知の宛先は、前述のとおり、運営者ではないかもしれない。

第三に、公的機関の実務では金額より手続きが重い。金額が事前に確定しない外国企業へのクレジットカード払いは、公金の支出として通しにくい。

要するにカード登録とは、「フォームが止まるリスク」を「請求額が確定しないリスク」に交換する操作である。どちらを選んでも、主導権は運営者の側にない。

## 理由3:止めたい相手を通し、通したい相手を止める

無料枠の問題を離れても、防御性能そのものに問題がある。

CAPTCHA の解決を代行するサービスは以前から存在し、相場は1件あたり1円に満たない。攻撃者はこれを使って通過する。reCAPTCHA v3 は通信の「怪しさ」を確率的に採点する仕組みであり、突破を前提とする相手には効果が限定的である。排除すべき相手は、今も通過し続けている。

一方で、規約に従う自動化は止まる。Anthropic を例にとる。2026年3月、デスクトップアプリに「Computer Use」機能が搭載され、Claude が画面を認識し、マウスを動かして、人間と同じように Chrome を操作できるようになった。同じ時期に、CLI 版の Claude Code からも、MCP(Model Context Protocol)経由で Chrome DevTools や Puppeteer を接続してブラウザを制御する構成が確立し、ブラウザ拡張「Claude in Chrome」も提供されている。ブラウザ操作・フォーム入力は、いまや公式機能として文書化されている。そして公式ドキュメントには、CAPTCHA やログイン画面に遭遇したら処理を停止して人間に委ねる、と明記されている。同種の機能は他社のエージェントにも広がっている。

ここで注目すべきは、フォームの自動操作が、秘匿される攻撃手法ではなく、文書化された標準機能になったという事実である。「フォームは自動で操作できる」という認識は、一部の技術者の知識から、誰もが触れられる常識へ移りつつある。

そして、この普及には非対称がある。規約に従う正規の自動化は、設計どおり CAPTCHA で停止する。規約を無視する自動化は、解決代行を使って通過する。CAPTCHA が選別しているのは、人間か機械かではなく、規約を守るかどうかである。守る側だけが止まり、守らない側は通る。攻撃者が規約を守らないのは当然の前提だから、この選別は防御として機能していない。

### 変わったのは能力ではなく、頻度である

この状況を、特定のツールが公開されたせいにするのは正確でない。停止ロジックを持たない自動化も、解決代行サービスも、以前から存在した。熟練した攻撃者にできることの上限は変わっていない。

変わったのは頻度である。エージェント型ツールが誰でも触れる形で普及し、「フォームは自動で叩ける」という認識が一般化すれば、試みる人間の数が増える。防御にとって効くのは能力の上限ではなく試行の頻度であり、これは実質的な脅威度の上昇である。

この敷居の低下は不可逆で、個々の製品名を超えて進む。攻撃側の敷居は数か月単位で下がり、防御側のフォームは数年単位で更新されない。この速度差が、問題の本体である。

## 対処:Turnstile への置き換え

Cloudflare Turnstile は無料で、回数制限がなく、クレジットカードの登録も不要である。WordPress には連携プラグインがあり、Contact Form 7 など主要なフォームプラグインに対応する。

ただし、Turnstile は時間稼ぎである。人間か機械かを判定する仕組みである点は reCAPTCHA と同じで、AI エージェントは Turnstile も通過できる。違いは、通過に時間とコストがかかることである。攻撃を止めることはできないが、割に合わなくすることはできる。

稼いだ時間で、認証の設計に移る。
