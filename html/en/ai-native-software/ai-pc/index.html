Give the AI
a PC of its own.

Turn one company PC into Debian and hand it over, root included. The human keeps only what a reinstall cannot restore

2026.09.20 🌐 日本語

Everything the Independence part stands up has to run somewhere. Decide where, first.

2-01 drew the map: the layers bundled inside Microsoft and Google, untied into open tools. This chapter is about the machine those tools sit on. There is one move. Turn one company PC into Debian and hand it to the AI. Give the AI a PC of its own. Everything the following chapters stand up runs on that one machine.

One machine does everything

The public website, the in-house tools (auth, documents, mail, meetings, scheduling, the code repository), and the AI's own work all go on the same machine.

There is no reason to split them at the start. Every extra machine multiplies the configuration and the updates. And the AI diagnoses and repairs faster when it can see the whole machine from inside. When the load outgrows one box, split it then.

Debian is the base; Windows runs in a box

The base is Debian. Python, git, and apt are there from the start. Updates never reboot the machine on someone else's schedule.

Anything that only runs on Windows is not thrown away. Run Windows in a virtual machine inside Debian (GNOME Boxes) and use it there. Accounting software with no substitute is the usual case. It is still one PC.

This is the reverse of WSL. WSL puts Linux inside Windows. This puts Windows inside Debian. Debian is the base and Windows is the guest. The data and the code live on the base, so Windows updates and restarts no longer reach them.

The virtual machine has one more advantage: snapshots. Take a snapshot before installing anything, and you can go back. A macro in a file that arrived by mail stops inside the box.

Install a desktop and leave it running

Install the desktop environment (GNOME) as well, and leave it running. Do not assume a server needs no screen. Some of the work you want the AI to do requires one.

  • Open a document on screen and read the values out of it
  • Look at a page you built, in a real browser
  • Drive the Windows guest and use a tool that runs nowhere else

When a person needs to look, they connect to that desktop from their own PC. That connection is never opened to the outside.

Hand the AI root

The AI does all the server configuration: installing, configuring, running, repairing. Every one of those is work in commands and files, and the result can be checked mechanically. It falls squarely inside what 1-01 described as a domain with fixed rules, where the answer can be verified.

There is one reason it is safe to hand over the privilege. If it breaks, you reinstall and start again. On a PC, that restores it. So the human keeps only what a reinstall cannot restore, which is the next two sections.

Run more than one AI, and have them watch each other

Do not run a single AI. Run several. Not depending on one vendor is the same reasoning as not depending on one SIer (3-03).

Then have them check each other. Pair AIs from different vendors, and give the checking side only the artifact and the criteria. Do not give it the history of how the thing was built. An AI that shares your reasoning shares your blind spots.

The human keeps only what a reinstall cannot restore

  • Keys and accounts — domain registration and anything tied to payment never live on this machine
  • Actions taken outside it — changing DNS, sending mail, deleting data in an external service. The AI states these before doing them, and a person approves
  • The documents themselves — keep copies off the machine

Everything other than these three can be left to the AI.

Separate the public side from the AI's side

  • The only ports open to the outside are 80, 443, and ssh
  • The desktop connection is not exposed; tunnel it from your own PC through ssh
  • The public website and the AI's work run as different users

The point is that a hole on the public side must not reach the documents and keys on the AI's side. What 2-04 says, *central minimal and defense in depth at every server*, does not change because there is only one machine.

What you need

  • One PC: 8GB of memory or more, 128GB of disk or more
  • An internet connection
  • The AI subscriptions

The server can be cheap hardware. If it breaks, replace it. No dedicated server machine, no maintenance contract.

What it costs

As of 2026-09-20, Claude's individual plans are $20 a month for Pro and from $100 a month for Max. Two of them are listed because you subscribe twice, so they can check each other.

Phase Subscriptions Per month
While building $100 + $100, or $100 + $20 $120–200
In steady operation $20 + $20 $40 (under ¥10,000)

In operation the AI's role is only to confirm things are running. You are not keeping an agent running continuously, so the flat plans are enough.

No approval process, no server contract, no per-seat licenses. One AI on this machine serves the whole group; you do not buy a seat per head. Commissioning an SIer does not buy much more than this. What hiring an SIer gets you, you can get for about $20 a month.

How to check you are done

This chapter is done when these six hold.

  1. You can ssh into the server from your own PC
  2. You can connect to the desktop from your own PC and see GNOME
  3. The Windows guest boots and you can take a snapshot of it
  4. docker compose version answers inside the server
  5. Seen from outside, nothing but 80, 443, and ssh is open
  6. Asking the AI to report the state of this machine produces a report
ssh builder@example.com            # 1
docker compose version             # 4
sudo ss -tlnp                      # 5 — list the open ports

What the human holds

Values the human supplies

  • The server's domain name
  • The ssh public key of the human's own PC
  • The name of the first administrator
  • The Windows license used inside the box

Actions the AI states before performing

  • Changing a DNS record
  • Opening a new port in the firewall
  • Reinstalling the operating system
  • Deleting a virtual-machine snapshot

Versions checked, and when

  • Debian 13 (trixie), GNOME, GNOME Boxes, Docker Engine + Docker Compose v2
  • Claude's prices were checked on 2026-09-20
  • This procedure was written on 2026-09-20
  • If a version has moved, have the AI confirm the official procedure before proceeding

Summary

Decide the machine the Independence part runs on, first.

  • One machine for all of it — public website, in-house tools, the AI's own work
  • Debian as the base — anything Windows-only runs in a box; the reverse of WSL
  • Install the desktop too — open documents, look at pages, drive the Windows guest
  • Root to the AI — safe to hand over, because a reinstall restores the machine
  • More than one AI — pair vendors and pass only the artifact and the criteria
  • Three things the human holds — keys and accounts, outside actions, copies of documents
  • Cost — $40 a month in operation, under ¥10,000 (as of 2026-09-20)
