# 方針: 図は Mermaid ではなく SVG(AI生成・凍結)

2026-07 のレビューでの決定事項。理由と運用をここに固定する。

## 理由(サイトの原則からの帰結)

- Mermaid は変換器(mermaid.js)を読者のブラウザに常駐させる方式で、
  「生成器をランタイムに残さず、凍結した成果物を配る」原則の逆になる。
  素の HTML/CSS/JS という本サイトの構成で唯一の実行時変換器
- 描画は mermaid のバージョンに依存し、同じソースでも将来同じ図になる
  保証がない。JS 無効・RSS・印刷では図が出ない
- レイアウト・フォントを制御できず、サイトの独立タイポグラフィの管理外
- Mermaid の存在意義は「人手で図を描くコストの回避」だった。AI が SVG を
  直接書ける今、利点は薄れ欠点が残る。SVG もテキストであり、git 差分・
  人の確認・凍結という他の成果物と同じ扱いに入る

## 運用

1. **新規の図は SVG**。Mermaid は新規記事で使わない
2. **既存60ファイルは一括変換しない**(上書きしない原則)。記事を改稿する
   ついでに1枚ずつ AI が描き直し、**人が目視確認してから**置き換える
3. mermaid.js の読み込みは、使用記事がゼロになるまで残す(後方互換)
4. mermaid-cli(ヘッドレス Chromium)によるビルド時変換は採らない
   (最小依存に反する)

## SVG の作法

- `viewBox` 必須。幅は CSS 側で `max-width: 100%`(レスポンシブ)
- 文字はアウトライン化しない(`<text>` のまま。検索・コピー・翻訳可能に)。
  フォントはサイトと同じ(Noto Sans JP / Zen Old Mincho)
- 色はサイトのパレットに合わせる。単色の線・文字は `currentColor` を使い、
  ダークモード等の将来変更に追従させる
- `role="img"` + `<title>`(+必要なら `<desc>`)でアクセシビリティを担保
- **意味の保存**: 元の Mermaid DSL(または図の意図の日本語記述)を SVG 内の
  `<desc>` か、同じ記事フォルダのサイドカー(`flow.mmd` 等)に残す。
  後で AI に図を修正させるとき、幾何ではなく構造から編集できるように
- 1記事=1フォルダ規約のとおり、SVG は記事フォルダに置く(`en-` プレフィ
  クスの言語別配信規則も画像と同じ)

## 移行の進め方(依頼テンプレート)

記事単位で依頼する。例:

> articles/blog/021-software-three-transitions/ の Mermaid 図を SVG に
> 置き換えて。docs/plan/mermaid-to-svg.md の作法に従い、元の DSL は
> <desc> に残す。ja/en 両方。置き換え後、ビルドして表示を確認する。

パイロット候補(閲覧が多い・図が単純な順に2〜3記事)から始め、作法が
固まってから残りを順次。
