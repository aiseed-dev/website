AI に、PC を一台渡す。

会社の PC を一台 Debian にして、root ごと AI に渡す。初期化で戻らない物だけ、人が持つ

2026.09.20 🌐 EN

自立編で立てるものは、全部どこかで動く。その置き場を、最初に決める。

2-01 で、Microsoft と Google に束ねられた層を、開いた道具に解く地図を引いた。この章は、その道具を載せる機械の話だ。やることは一つ。会社の PC を一台 Debian にして、AI に渡す。AI にも専用の PC を一台あげる、ということだ。以降の章で立てるものは、全部この一台の上に乗る。

一台で全部やる

公開の Web サイト、社内の道具(認証・文書・メール・会議・予約・コードの置き場)、AI の作業を、同じ一台に載せる。

最初から分ける理由はない。台数が増えれば、設定も更新も台数分になる。そして、 AI が一つの機械の中で全部を見られるほうが、調べるのも直すのも速い。処理が足りなくなったら、そのときに分ければいい。

Debian を土台にして、Windows は箱の中で動かす

土台は Debian にする。Python も git も apt も最初から入っている。更新で勝手に再起動されることもない。

Windows でしか動かない物は、捨てない。Debian の中の仮想環境(GNOME Boxes)で Windows を動かして、そこで使う。会計ソフトのような、代わりの無い物のためだ。 PC は一台のままである。

これは WSL の逆だ。WSL は Windows の中に Linux を入れる。こちらは Debian の中に Windows を入れる。土台が Debian で、Windows が客になる。データとコードは土台の側にあるので、更新や再起動が Windows の都合で降りてこない。

仮想環境には、もう一つ利点がある。写し(スナップショット)を取れることだ。何かを入れる前に写しを取れば、気に入らなければ戻せる。メールで届いたファイルのマクロが動いても、箱の中で止まる。

画面を入れて、動かしたままにする

デスクトップ環境(GNOME)も入れて、起動したままにする。サーバーだから画面は要らない、とはしない。AI にやらせたいことの中に、画面が要るものがあるからだ。

  • 文書を画面で開いて、中の値を取る
  • ブラウザで、作った頁を実際に見る
  • 箱の中の Windows を動かして、そこでしか動かない道具を使う

人が見るときは、手元の PC からその画面につなぐ。この接続は外には開けない。

AI に root を渡す

サーバーの設定は、全部 AI がやる。入れる、設定する、動かす、直す。どれも命令とファイルの仕事で、やった結果が機械で確かめられる。1-01 で見た ルールが決まっていて、答え合わせができる領域 に、そのまま当てはまる。

権限を渡してよい理由は一つだ。壊れても、初期化して始め直せる。PC ならそれで戻る。だから、初期化で戻らない物だけを人が持つ。それが下の二つの節だ。

AI を複数入れて、相互に見張らせる

AI は一つにしない。複数入れる。一社に頼らないのは、SIer に頼らないのと同じ考えだ(3-03)。

そのうえで、相互に見張らせる。別の会社の AI を組ませ、見張る側には 作った物と、確かめる基準だけ を渡す。どう作ったかの経緯は渡さない。同じ経緯を共有した相手は、同じ見落としをする。

初期化で戻らない物だけ、人が持つ

  • 鍵と認証 ── ドメインの登録、支払いに関わるサービスの認証は、この機械に置かない
  • 外でやる操作 ── DNS を替える、メールを送る、外のサービスのデータを消す。この類は、AI が「やる前に言う」形にして、人が通す
  • 書類そのもの ── 機械の外にも写しを置く

この三つ以外は、AI に任せてよい。

公開の側と AI の側を分ける

  • 外に開ける入り口は、80 と 443 と ssh だけにする
  • 画面への接続は外に開けない。手元の PC から ssh の中を通す
  • 公開の Web と AI の作業は、別の利用者で動かす

公開の側に穴が出たときに、AI の側の書類と鍵に届かないようにするためだ。 2-04 で書く「中央は最小限、守りは各サーバーで多層に」は、機械が一台でも変わらない。

要る物

  • PC が一台。メモリ 8GB 以上、ディスク 128GB 以上
  • インターネットの回線
  • AI の利用料

サーバーは安い物でよい。壊れたら取り替える。専用のサーバー機も、保守契約も要らない。

費用

2026-09-20 時点で、Claude の個人向けは Pro が月 20 ドル、Max が月 100 ドルからだ。二つ並ぶのは、相互に見張らせるために二契約するからである。

時期 契約 月額
開発のあいだ 100 ドル + 100 ドル、または 100 ドル + 20 ドル 120〜200 ドル
運用に入ったら 20 ドル + 20 ドル 40 ドル(月 1 万円以内)

運用での AI の役割は、動いているかの確認だけになる。エージェントとして走らせ続けるわけではないので、定額で足りる。

稟議も、サーバーの契約も、人数分のライセンスも要らない。AI はこの一台に入れれば、グループの全員が使う。人数分の契約は要らない。SIer に委託しても、やっていることは大きくない。SIer を雇うのと同じことが、月 20 ドルほどでできる。

確かめ方

この章は、次の六つができていれば済みだ。

  1. 手元の PC から、ssh でサーバーに入れる
  2. 手元の PC から画面につないで、GNOME のデスクトップが見える
  3. 箱の中の Windows が起動して、写しが取れる
  4. サーバーの中で docker compose version が返る
  5. 外から見て、80 と 443 と ssh 以外の口が閉じている
  6. AI に「この機械の状態を報告して」と言うと、報告が返る
ssh builder@example.com            # 1
docker compose version             # 4
sudo ss -tlnp                      # 5 ── 開いている口を見る

人が持つ物

人が渡す値

  • サーバーのドメイン名
  • 手元の PC の ssh 公開鍵
  • 最初の管理者の名前
  • 箱の中で使う Windows のライセンス

AI が「やる前に言う」操作

  • DNS のレコードを変える
  • ファイアウォールの口を新しく開ける
  • OS を初期化する
  • 仮想環境の写しを消す

確かめた版と日付

  • Debian 13(trixie)、GNOME、GNOME Boxes、Docker Engine + Docker Compose v2
  • Claude の料金は 2026-09-20 に確認した
  • 手順を書いたのは 2026-09-20
  • 版が上がっていたら、AI に公式の手順を確かめさせてから進める

まとめ

自立編を動かす機械を、最初に決める。

  • 一台で全部 ── 公開の Web、社内の道具、AI の作業を、同じ機械に載せる
  • 土台は Debian ── Windows でしか動かない物は、箱の中で動かす。WSL の逆
  • 画面も入れる ── 文書を開く、頁を見る、箱の中の Windows を使う
  • AI に root ── 壊れても初期化で戻るから渡せる
  • AI は複数 ── 別の会社の AI に、作った物と基準だけを渡して見張らせる
  • 人が持つのは三つ ── 鍵と認証、外でやる操作、書類の写し
  • 費用 ── 運用は月 40 ドル、月 1 万円以内(2026-09-20 時点)
